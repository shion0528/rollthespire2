# Production CPU execution integration checks

These checks call the production `FamilyCpuExecution` from the built mod assembly. They do not copy or reimplement the executor. Synthetic requests omit gameplay authority; only the Beta111 seed profile and immutable run options are used by these paths.

After the main project is built centrally, build this console project with `-p:BuildProjectReferences=false`, or pass `-p:Rt2AssemblyPath=<absolute built RolltheSpire2.dll>` and `-p:Rt2AssemblyDirectory=<its directory>` to reference that exact artifact. The default project reference carries `AdditionalProperties="Rt2ModsDir="`; no main-project build is needed when using the explicit assembly path. Run the resulting `ProductionSearchHost.dll` with `dotnet`. A successful run ends with `RT2_CPU_INTEGRATION {"phase":"complete","result":"PASS",...}`. This project has no test-framework package dependencies.

Coverage includes 1/32/64 worker requests, effective budget enforcement, both numerical-byte roots and formatted-profile roots, dense and compact ordinal identity/order, zero/tiny inputs, 8192-root window boundaries, multiple private windows, seed carry near the visible-space end, null-budget parity, pre-start/in-flight cancellation and successful reuse, and actual CPU partitions sharing permits with a competing Exact-like job. A 64-worker request on a 32-logical-processor host correctly uses 32 workers; the output reports the effective values.

`CpuExecutionIntegration.Run(Action<string>)` is reusable from the existing Godot GPU smoke host if the standalone console cannot load the engine's managed dependencies. Include `../CpuExecutionChecks/CpuExecutionIntegration.cs` in that host project and call `CpuExecutionChecks.CpuExecutionIntegration.Run(message => GD.Print(message))` before its GPU checks. This keeps the same real production executor and assertions inside an initialized Godot process.

The same console then runs `ProductionSessionIntegration`, which uses controlled Family/Exact seams around the real `ProductionSearchSession`. It checks a complete nine-batch scan and contiguous cursor, empty-terminal bypass, cancellation with a deliberately unfinished early survivor and completed later survivors, safe resumption, Exact fault preservation while draining, GPU-zero admission before device creation, and actual Family CPU partitions overlapping actual Production Exact under one session CPU ceiling. Each Exact result is NoMatch, so these fixtures need no gameplay authority or game session. The lifecycle runner has a 45-second outer timeout, and success ends with `RT2_SESSION_INTEGRATION {"phase":"complete","result":"PASS",...}`.

`--portability` runs only the short `CpuPortabilityIntegration` checks. Its parameter matrix covers 1/2/4/8/16/24/32/64/96/128 logical processors; preference cases call the real migration helper. An old worker-only preference copied before migration retains its worker count where representable (16 workers on 64 threads becomes 25%); a saved 50% preference copied after migration scales to 32 workers on that machine. Integer percentage granularity means an old 1-worker setting on 128 threads becomes 1%, or 2 workers. The runtime ceiling remains 64 even on 96/128-thread machines.

For process-level simulation set `DOTNET_PROCESSOR_COUNT=4` or `64` before launching a new `dotnet ... --portability` process. Setting both `DOTNET_EnableHWIntrinsic=0` and `COMPlus_EnableHWIntrinsic=0` additionally checks that actual production root filtering succeeds with vector/AVX2/SSE2 reporting disabled. The probe verifies those flags took effect and exercises real P63/P64 configuration while admitting only two tiny partitions at once. Its output explicitly labels processor-count overrides as simulations; these are not tests on separate physical 4/64-core machines, AMD processors, or ARM64. Native Godot/game dependencies, other operating systems and GPU vendors require their own hardware validation.
