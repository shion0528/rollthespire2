## 各表的基线与边界

本资料整理于2026-10-27，没有重新测速。所有速度来自已完成的历史测量。

- 全量34项：resource.15 对上游v1.3.5提交 `77a7dbedd67b6e7cbe69caa30a4f6d3f28dad1f8` 的独立源码Release构建，双方加入同一观察器。不是当前resource.17对原版的全量复测。
- 后续resource.15复测A/B是独立场次，分别保留，未把它们与旧全量合成平均值。F02/F03/F06出现负值或方向翻转，不能宣传稳定提升。
- resource.16公平对照采用同一轻量连续结果读取器。实际接收器30/60FPS压力观察是另一套协议，不含完整界面持久化和渲染。
- resource.17三轮均对照resource.16，仅第三轮的同候选开局推演复用进入正式版。不同版本、协议的百分比不能相加或叠乘成resource.17对原版的速度。
- 每场景每版本两次约10秒，顺序为基线所有场景、候选所有场景、第二轮；CPU场景置于各版本末尾。预热、启动、编译和收尾不算在这10秒内。
- 完整Exact验证保留。候选数统计可能包含预热和收尾，不能直接除以10秒当作测量窗口内的匹配速率。
- 两次短测只能描述本机本次表现，不能证明统计显著或跨机器同幅提升。硬件利用率采样不是GPU内核计时。

## 计算口径

1. 单轮速率 = 计时窗口已完成种子数 / 该窗口实际秒数。
2. 合并吞吐 = 两轮已完成种子数之和 / 两轮实际秒数之和。
3. 算术均速 = 两轮速率的算术平均。
4. 对照提升 = 候选速率 / 对照速率 − 1。表格分别列出合并吞吐提升、算术均速比提升及两轮配对提升，不混用。
5. resource.17的F02 `44.4752%` 是算术均速比提升；合并吞吐提升为 `44.4779%`；两轮提升百分比的算术平均为 `44.6381%`。旧文档曾把第一种误称为第三种，本公开整理已更正。

## 正确性与局限

全量34项固定范围的两版完整结果列表一致，但其中10项验证范围内没有完整命中。双空集不足以证明全部正向分支；不能把有限范围一致写成全空间证明。各项验证范围、命中数和已知正例记录在JSON中。

主表完整保留正负结果和逐轮波动。后续复测出现半速形态，原因没有被唯一隔离；不直接归因于休眠、垃圾回收或某一项优化。接收器30/60FPS压力测试缓冲没有填满，观测差异不能解释为已证实的满队列阻塞。

随附输入、每轮计数和秒数可核对表格计算。完整历史自动化环境未作为可一键运行的工具发布；源码构建说明与测试输入不等于保证复现同一速度。
